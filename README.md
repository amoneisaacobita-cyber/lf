# Life Fountain Church

A responsive, server-backed church website with member pages for sermons, short videos, prayer requests, daily verses, a searchable King James Version Bible, church information, and community. The Admin dashboard manages pastors, prayer follow-up, church details, and custom daily verses; the separate Streaming studio contains live-audio and media-publishing controls.

## Run it

Install Python 3.10 or later and FFmpeg, then run `start.bat` on Windows or `python server.py` from a terminal. Open `http://127.0.0.1:8000`. Keep the server window open while using the site. On first startup, the server prints a one-time administrator setup code. Enter that code in the site and create an administrator account with a unique password of at least 8 characters. The setup code is removed after the admin account is created.

The Streaming studio appears in the church-tools menu for everyone and has a separate password gate. Configure its password through the `LFC_STUDIO_PASSWORD` environment variable before the first server startup; the initial value is saved as a password hash in SQLite. On this existing local installation, the studio password was set separately by the administrator. After unlocking the studio, an admin or pastor account is still required to start/stop broadcasts or publish content.

## Deploy to Render

This repository includes a Render Blueprint (`render.yaml`) and a Dockerfile. In Render, create a **Blueprint** from the GitHub repository and deploy the `life-fountain-church` web service. The Docker image installs FFmpeg, and the service binds to Render's `PORT` on `0.0.0.0`. The Blueprint also creates a 25 GB persistent disk at `/var/data` for the SQLite database, recordings, and uploads; adjust its size to suit your storage needs. A persistent disk requires a paid Render instance and incurs disk charges. Do not remove the disk or change `LFC_DATA_DIR` unless you have backed up and migrated the data.

When prompted, set `LFC_STUDIO_PASSWORD` to a strong, private value in Render. The first deployment prints a one-time admin setup code in the service logs; use it to create the administrator account, then the code file is removed. Set any changed environment variables in Render and redeploy. The app enables secure cookies because Render terminates HTTPS in front of the service. This SQLite-backed deployment is intended to run as one web-service instance; multiple instances must not share the same SQLite database.

## Server-backed features

The Admin dashboard creates pastor accounts and stores prayer requests and responses in SQLite. Pastors sign in with their own account and can only view/respond to requests assigned to them; the admin can view all requests. In the Streaming studio, enter a stream title, allow microphone access, and start the broadcast. The browser uploads audio segments to the server; members can select **Listen to the live audio** on the home page to hear them. A separate uninterrupted 16 kHz WAV recording is saved when the broadcast stops, so saved sermons use a broadly playable format rather than a concatenation of live-stream segments. Set an optional wallpaper before going live; it fills the live broadcast card with a dark text-contrast overlay and remains attached to the saved recording. Admins can delete uploaded sermons and completed live recordings from the sermon library; deletion removes the associated saved audio and wallpaper. Admins and pastors can upload short videos, which are saved on the server and playable on the site. Sermon videos are converted to MP3 for audio playback. Data and recordings persist under the `data` directory. Back up this directory to preserve the database and audio.

Admins can also update the public **About us** details and location in the Admin dashboard. Add both latitude and longitude to show the church pin on the map and enable directions; without coordinates, the map remains hidden. Admins can upload or remove a JPG, PNG, or WebP church logo (up to 2 MB); it is used in the sidebar branding and startup animation. The **Announcements** page is available to members and staff. Admins and pastors can publish updates to everyone or to pastors only; pastor-only announcements are filtered on the server and require staff sign-in. Custom verses added in the dashboard appear in the daily verse rotation and public daily-verse page. The **King James Bible** page includes all 66 books, chapter navigation, and text/reference search.

Admins and pastors can publish a sermon directly from an audio upload, with a heading and optional wallpaper, without video conversion. Supported formats are MP3, WAV, M4A, OGG, WebM, FLAC, and AAC (up to 100 MB). Video sermons use resumable 16 MB chunks and can be up to 20 GB, including files over 5 GB; the server assembles and converts the video to MP3 without loading the complete source into memory. Re-select the same video in the same browser tab to resume an interrupted upload or retry conversion. Conversion time depends on video duration and server performance. Complete audio files added to `data/media` or an ordinary subfolder such as `data/media/sermon-imports` are automatically added to the sermon library, including a matching same-name JPG, PNG, or WebP wallpaper, or a folder-level `cover`/`wallpaper`/`background` image. Wallpapers display without cropping over the sermon artwork. The server ignores its managed `data/media/media` upload and `data/media/church-brand` logo folders, and waits for a new file to stop changing before importing it. Admins can rename sermons and completed live recordings from the sermon library. Each published sermon and saved live recording shows a playback count; a count is added when playback starts.

The Bible text is provided locally by [`bible-kjv.json`](./bible-kjv.json) from the [Bible-kjv dataset](https://github.com/aruljohn/Bible-kjv). Its MIT license and copyright notice are included in [`BIBLE-DATA-LICENSE.txt`](./BIBLE-DATA-LICENSE.txt).

## Deployment and media notes

The included server binds to `127.0.0.1` for local use. For public access, deploy behind a properly configured HTTPS reverse proxy, set `LFC_HTTPS=1`, configure firewall and backups, and use a production WSGI/server stack with monitoring and access controls. Do not expose the development server directly to the internet. Browser microphone capture requires HTTPS for non-localhost addresses.

The included sermon and short-video catalog includes sample content; real uploaded videos and converted audio appear alongside it. If FFmpeg is not on the system PATH, set `LFC_FFMPEG_PATH` to its full executable path. Audio segments are served to listeners from this server, so public hosting needs adequate bandwidth and disk capacity. Configure admin and stream credentials via a secrets manager or environment variables; never place passwords in browser code or source control.
